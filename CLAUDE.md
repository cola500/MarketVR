# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

"MarketVR" (formerly "Lilla fruktståndet"; the Android application id `com.lillafruktstandet.prototype` and the C# namespaces `Fruktstand.*` keep the old name): a small Quest 3 VR game where a child runs a little market: fruit & veg, candy and toys, a shared till, children playing at a play table, a crocodile game, a market party and rest break, and a parent who can shop and pause from a phone. Spec-driven: `docs/SPEC.md` (rules, interaction, scope), `docs/EPIC-00N.md` (stories, acceptance criteria tied to test names, verification log; EPIC-004 = parent as a customer from the phone, preceded by `docs/SPIKE-004.md`; EPIC-017 = playing together at the play table, EPIC-018 = hopping frogs), `docs/PLAYTEST.md` (user tests and which build id each one used). Docs are Swedish; code and comments are English. Keep the spec and epic up to date when behaviour changes, and keep "automated test" / "build" / "headset (developer)" / "child playtest" claims separate.

`../magic-tiles-snapping` and `../CampfireVR` are separate projects: read-only. Never modify them or kill their Unity processes.

## Commands

Unity 6000.4.7f1. The project must not be open in the editor while these run.

```sh
scripts/quest.sh snapshots # off-headset renders (Snapshots tests, graphics), watched; PNGs in UnityProject/Logs/shots/
scripts/quest.sh test     # EditMode + PlayMode (batchmode, -nographics) with live progress; a run is stopped when no test
                          # finishes for TEST_STALL s (120, names the test) or after TEST_TIMEOUT s (600); TEST_FILTER=<regex>
scripts/quest.sh scene    # regenerate Assets/Scenes/FruitStand.unity via SceneSetup
scripts/quest.sh build    # APK -> Builds/LillaFruktstandet-quest.apk + archived Builds/archive/lilla-fruktstandet_<id>.apk/.json
scripts/quest.sh install <id|apk>  # adb install -r of an archived build (never uninstall): manifest checked, refused while the
                          # app is in front, installed build id verified; then: launch / log
scripts/quest.sh devices | wifi | connect [ip] | disconnect  # wireless ADB (README); every adb call uses -s <device>
scripts/test/quest-install.test.sh  # the device/install logic against a fake adb (never a real headset)
scripts/quest.sh builds | installed
scripts/kund.sh start | test | spike [beacon]   # phone-customer relay (Node 22+, no npm), its tests, Editor chain
scripts/park-assets.sh [list]   # EPIC-013: unpack the 13 selected park files from the cached Asset Store package (git-ignored)
```

Build ids are `<Stockholm date>_<time>_<sha>[-dirty]`; archived builds are read-only and never deleted. versionCode stays 1 (adb install -r accepts equal codes); versionName is `1.0+<id>`, and the menu shows the id. Record a tester's build id in PLAYTEST only once it is confirmed on the headset.

Single test: `TEST_FILTER=<name> scripts/quest.sh test`. Always run Unity tests through `quest.sh` (`test`/`snapshots`): it shows progress, stops a hung run and saves a stack sample. PlayMode tests load the scene with `SceneLoad.Fresh` (synchronous), never `LoadSceneAsync`: that deadlocks the editor against deferred `Destroy` of renderers using imported meshes. Rules and the 5-whys: `docs/TESTING.md`. Off-headset renders: `scripts/quest.sh snapshots` (the explicit `Snapshots` tests, needs graphics). Compile errors show as `error CS` in `UnityProject/Logs/*.log`.

## Architecture

- `Fruktstand.Core`: pure rules. `Market` holds `Shop`, `Wallet`, `PlayArea` and `RemoteCustomer`; `NewGame` is the only reset of the till. The till (`Wallet`) is credited only in `Shop.TryPay`, with the order's sum. `Shop.SetOpen(false)` stops only new customers (`Closed` state); `ClearBasket` restarts only the current order. `Shop` is the sale state machine (CustomerArriving → Ordering → AwaitingPayment → Thanking → CustomerLeaving). The sale is registered only by `TryPay` in AwaitingPayment (exactly once). The basket locks when it matches. `OrderGenerator` uses its own PRNG; customer 1 always wants one apple. `DropRules` decides basket/register/home from counter-space positions.
- `Fruktstand.Game`: `FruitStand.Step(ShopFrame)` is the single entry for VR, desktop and tests. `Grabber` (pure) grabs only on a fresh press. Items never fall freely: a release outside a zone sends them home. Views are built at runtime from primitives (`Art`, `Models`, `StandView`, `CustomerView`, `OrderBubble`); the scene only references meshes/materials/font so they ship in the build. Exception: every ware is a Blender model, `Models/<Ware>.fbx` (+ `Ring`/`RingPeg` play pieces), generated by `art/{fruit,candy,toys}/make_*.py` on the shared `art/kit.py` (`blender -b --factory-startup -P <script>`; never edit an FBX by hand). They are imported without materials, their submeshes are coloured from `Models.ModelColours`, and `Models` falls back to primitives if a mesh is missing. Toy colliders come from `PlayTableView`, not the models. See `docs/SPIKE-BLENDER.md`. Use `Art.Discard` (not `Destroy`) when rebuilding views.
- `Game/Xr`: `XrRig` reads both controllers via `UnityEngine.XR.InputDevices` (no XRI/Input System). `XrInputRouter` (pure) blocks play without focus/paused/headset off, sends held items home (`ReleaseAll`), and requires neutral buttons after any interruption or menu close. Sticks (EPIC-005, seated play): left = walk (`ShopFrame.Walk`), right = 30° snap turn or counter height, whichever axis it locked onto (`RightStick`). `XrRig` applies them through `Locomotion` (rig moved/turned around the head, never vertical; the tracked head pose is never touched), walking is stopped by `MarketCollision` footprints via `FruitStand.ConstrainWalk`, and `ShopFrame.RigDelta` keeps the rig's motion out of throw speed. Meta button is never read. Logs use the `[Fruktstand]` prefix.
- EPIC-003 compact market: `MarketLayout` (three shallow stalls + play table in a U round a 1.1 x 1.1 m work area, physical space assumed 1.5 x 2.0 m; locked by `Layout_*` tests; plan view in SPEC §14). One active order at a time (`Shop`), shared till (`Wallet`, credited with `Order.Sum` in `TryPay`), `PlayArea` + `PlayTableView` (children, toy physics stepped from `Step`). No teleporting: the player turns and steps; the market is only placed on start/recenter/menu (`StandPlacement`). The Öppet/Stängt signs flip when an empty hand moves through them (`TouchSwitch`).
- EPIC-004 phone customer: the Quest is authoritative. `Core/RemoteCustomer` turns phone *requests* into an ordinary `Order` on the next free customer turn (never interrupts an NPC, no new NPCs meanwhile), is idempotent per order id, and is marked Done only from `Shop.TryPay`. `Game/Remote`: `RemoteSession` (protocol, no sockets, tested directly), `RelayLink` (UDP beacon port 47811 + `ClientWebSocket`, background thread, never started in batch-mode tests unless a test asks), `PhotoStore` (128 px raw RGBA, memory only), `Portrait`. The relay (`relay/`) only forwards `order`/`photo`/`sync` from phones and `hello`/`status` from the Quest. Verification levels in EPIC-004: [T] [E] (Editor chain) [B] [D] (devices) [P].
- EPIC-006 crocodile game: rules in `Core/CrocodileGame` (injected random; per-hand blocked-teeth mask so a resting hand never presses again; paused with menus/focus loss), shown by `CrocodileView` on its own shelf at the play table (`PlayTableView.ShelfCentre`/`CrocOrigin`, a `MarketCollision` footprint). Teeth are button `Item`s; `FruitStand` ticks the crocodile before setting their `Grabbable`. Only Nytt spel resets its count and the dance.
- EPIC-007 room alignment: `Calibration` (pure: preview area in tracking space, adjustments, confirm only if it fits) + `SpaceFit` (polygon fit, spacing `MarketLayout.StallDistance` 0.70–0.90, nothing scaled) + `RoomPlacement.ToWorld(rig)` (through the rig's current pose). `FruitStand.ShowPreview/ApplyPlacement`; the floor marking (`LayoutMarking`) is a child of the market root, built from the same layout, shown only while calibrating. `BoundaryProbe` only reads (Quest 3: size only, no points). `MarketLayout.StallDistance` is static: tests that change it reset it in `[TearDown]`, and `FruitStand.Awake` resets it.
- EPIC-008 party and rest: `Core/MarketRound` (earnings from `Shop.TryPay` only; Playing → PartyPending → Celebrating → Resting → next round; holds NPC customers and phone orders; threshold 80, developer `fest.txt`). `Market.Tick(dt, presentationReady, paused)` — the safe default is *not ready*. `PartyView` only shows (sign, party board, panels, bounded effects 2.45 m+). Phone parent commands are a separate `parent` message (rest/nextRound, idempotent per cmdId) through `RemoteSession.OnParentCommand`; the market status (`market`) is pumped separately from order status.
- EPIC-012 pauses and menus: `MarketRound.RestBy` (Child / Parent / Party): a child's rest ends with the menu's "Fortsätt spela" (`Market.Resume`), a parent's pause only by the parent (VR parent page or phone `resume`), the party rest only by `StartNextRound`; a plain pause never redraws wares. `GameMenu` pages are rows of buttons (`Rows()`); `MenuLayout` (pure) wraps and places them; `MenuPanel` draws them on top of the world (shader `Fruktstand/MenuOverlay`) and hit-tests the rays; `XrInputRouter.PointAt` turns a ray + trigger into exactly one click (`ClickedHand`).
- Do not install or relaunch on the headset while the child is playing; wait for the parent's go-ahead.
- EPIC-009/010 assortment: `Core/Assortment` (own `Prng`) offers three wares of every category (`WareInfo.Catalogue`: 8 fruit/veg, 8 candy, 7 toys); bins come from `Assortment.Bin`, never from the ware's index. Redrawn on Nytt spel and, for the next round, in `Shop.NextCustomer` once no phone order is open. `FruitStand.AssortmentChanged` rebuilds every stall but never touches carried, paid or played toys. Tests fix the start wares with `SceneLoad.Fresh(..., wares)` (`FruitStand.StartWares`; categories not given are classic); the app draws from the clock.
- Play table code: `PlayTableView` keeps the shared flow (walk, seat, control and rest, physics, lost toys, take/let go/send home); each toy is a nested `ToyPlay` in its own file (`PlayTableView.Ball/Top/Vehicle/Rings/Blocks/Frogs.cs`) with its own state, called at fixed hooks in the same order as before.
- EPIC-010 play zones: `PlayArea` has three zones (left ball/top, middle car/train on the road, right blocks/rings), one child each; a zone remembers its toy (`ToyIn`), so play outlives an assortment change. Physics budget `PlayArea.MaxBodies` = biggest toy per zone (8). `PlayTableView`: the child spins the top, drives car/train (`OnRoad`), builds with the player (EPIC-017) / puts rings on the fixed peg (`Stacks`); kinematic stacked pieces count as still. EPIC-011: a released block is placed by `Core/BlockPlacement` (on top / lifted / nearest free / last valid; never left inside another block or the table); held toys don't collide; each piece has its own lost timer; bodies are limited (depenetration 0.3 m/s, spin 20 rad/s).
- EPIC-013 park: `ParkLayout` (pure: trees, bench, stones, grass, flower beds and the flat gravel path round the market, in market space; `ParkTests` keep every route and the market free) drawn by `ParkView` as a child of the market root (follows placement, never walking or counter height; no colliders, no shadow casting; package models merged into one mesh, flowers per colour). Trees/bench/stones are `MarketCollision.Obstacles` for stick walking; `Footprints`/`FootprintsAt` stay market-only (marking, calibration). The models come from the Asset Store package *Low Poly Environment Park* via `scripts/park-assets.sh` (git-ignored, Standard EULA: never commit them); without them the park has no models and the game is unchanged.
- EPIC-014 atmosphere: `ParkLayout` also holds seeded tree/bush groups (mid ~7.5 m, far ~15 m) round the park with open sightlines along the path; `ParkView` adds far hills. Nature sound: `Core/Ambience` (pure: sporadic birds 7–18 s, no repeats, clock stops while paused, Normal/Low/Off), `NatureSounds` (3D bird sources in `ParkLayout.BirdSpots`), clips from `SoundSynth.Birds` (synthesised, no files). No looping wind/ambience bed: the parent found it tiresome on the headset. The setting is on the VR parent page (`MenuAction.CycleNatureSound`), kept in PlayerPrefs (never in batch mode).
- EPIC-015 park visitors: `Shop.WaitsForArrival` (set by `FruitStand`) holds CustomerArriving until `CustomerArrived()`; `CustomerView` walks `ParkRoutes.Arrival` (gate -> loop -> counter) and steps out on `Departure`; when the counter is free `FruitStand.HandOverLeavingCustomer` gives the figure to `ParkVisitors` (walk/bench/exit, poses), rules in `Core/ParkVisits` (weighted choice with injected random `FruitStand.StrollRandom`, one bench seat, `MaxVisitors` 2). A child after playing comes via `PlayTableView.ChildWentHome`. `ParkRoutes.WalkSpeed` is static: tests not about walking may raise it and reset it.
- EPIC-016 polish: `Game/Pacer` (pure) keeps every walking figure's distance (soft braking over `RampSeconds`, a small step aside on the gravel, priority at meetings: customer first, then the visitor who came first; never held longer than `MaxWait`); `CustomerView` and `ParkVisitors` step it, playing children (`PlayTableView.AddChildren`), the customer at the counter and bench sitters are `Walker.Standing`. `Core/ArrivalChime` decides the one 3D arrival pling per customer (`Sounds.Arrival`, at the active stall; muted behind menus/focus loss/rest, never played later); `StandView.ShowWaiting` hangs a small bell on a string from the awning (right of the customer, in a seated child's view) while the customer waits. No spatializer plugin: Unity's built-in 3D panning.
- EPIC-017 shared play: `Core/BallToss` (pure: a lifted ball let go moving forward is a soft arc, exactly to `PlayTableView.CatchPoint` within 35°, its speed from the plan, never the hand) and `Core/BuildSite` (pure: 3 x 3 cells, stable cells, the child's order, snap near the hand, turns with a beat and a time-out that waits while the player holds a block). `PlayTableView` catches (`BallCatches`), splits the blocks (`IsChildsBlock`; the child never moves one the player touched) and keeps built blocks kinematic in their cells (`Build`). `PlaySequences` (explicit) replays the two play sequences with simulated hands and renders them.
- EPIC-018 hopping frogs: `Ware.Frogs` (left zone, no bodies). `Core/FrogPond` (pure: press -> release = one hop, a fixed arc in the frog's facing; generous lily pad; frogs never land in each other; Fallen off the table until Reset; turns like EPIC-017). `PlayTableView.Frogs.cs` (`FrogsPlay`) draws the pond and poses the frogs; a frog's rear is an `Item.ForPress` (held while the grip is held, `Drop` = the hop, `SendHome`/`KeepFrogPresses` = cancel, so pause/menu/focus never leave a press behind). Models: `Frogs.fbx` (shop set) and `Frog.fbx` (play piece, coloured per owner) from `art/toys/make_toys.py`.
- Layout constants (reach for a seated child) live in `StandView` and `FruitStand.EyeToCounter/CounterBelowEyes`; SPEC §5 documents them.
- Don't add packages without a concrete need. Change the scene through `SceneSetup`, not by hand.

## Working rules

### Test-driven development

- New game logic and bug fixes are test-driven, in small cycles: write one relevant test, run it and see it fail for the right reason, write the smallest implementation that passes, then refactor while the tests stay green.
- A bug fix starts with a test that reproduces the bug, whenever that is practical.
- Test observable behaviour (rules, scene state, what the player sees or can do), not implementation details.
- Visual changes and XR behaviour that need the headset get concrete manual acceptance criteria (marked [H]/[P] in the epic) before implementation. Automated tests never replace the headset test; report them separately (see "What this is").
- Run the affected tests while working, and the relevant regression suites (`scripts/quest.sh test`, plus `scripts/kund.sh test` when the relay or protocol is touched) before delivering.

### Debugging with 5 whys

- Every failure whose cause is not obvious from the first look (a red test, a wrong number, a hang, a headset report) is debugged with 5 whys **before** the code is changed: ask "why?" from the observed symptom down to the root cause, and stop at the cause that, fixed, prevents the whole class of failure.
- Every answer rests on evidence, not on a guess: a log line, a stack sample, an instrumented assertion message (state, positions, speeds), or a small test that reproduces exactly that step. Mark an answer that is still a hypothesis as one, and verify it before building on it.
- Also ask why the failure was not caught earlier (a weak test, a missing check, a tool that hid it), and fix that too.
- Write the chain down briefly: in the epic's verification log for game behaviour, in `docs/TESTING.md` for test or tool problems (see its EPIC-009 example). The final report mentions it.
- No fix by trial and error: if a change does not behave as the chain predicted, go back to the chain instead of trying the next idea.

### Boy Scout Rule

- Leave the code a little better than you found it. A clear, nearby improvement of about 10–15 minutes is done on your own initiative, within the current work: simplify hard-to-read code, improve names, remove code confirmed unused, reduce local duplication, or correct misleading documentation (including this file).
- Preserve behaviour and verify it with the relevant tests. Keep the change small and easy to review, preferably in its own commit when that fits.
- Not under this rule: larger restructurings, dependency or package upgrades, and changes to game rules. Those need their own spec and the user's go-ahead.
- If an improvement grows beyond the time box, stop at a sensible boundary and note what remains (in the epic's log or the final report).
- In the final report, briefly list the improvements made and how they were verified.
